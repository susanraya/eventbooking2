<!-- sdlc:auto:start overview -->
eventbooking2 is a two-app repository generated by the Quorq AI SDLC platform for a basic event booking product. The frontend is an Angular 22 app (built with Vite via the Analog plugin) that renders a set of approved screens currently running on seeded sample data rather than live API calls. The backend is a Spring Boot 4.1 (Java 21, Maven) service with a Postgres-backed JPA data model for users, events, ticket types, consent records and audit logs; most endpoints are stubs except auth (register/login/logout), consent withdrawal, and event/ticket-type creation and listing, which are implemented. Supporting infra (Postgres, Meilisearch, Redis) is provided via docker-compose.
<!-- sdlc:auto:end overview -->

- Node.js (for npm/Vite/Angular 22 tooling)
- Java 21 JDK
- Maven (or use the included mvnw wrapper)
- Docker and Docker Compose (for Postgres/Meilisearch/Redis)

<!-- sdlc:auto:start setup -->
1. Clone the repository
2. Copy .env.example to .env and fill in required values
3. Run `docker-compose up -d` to start Postgres, Meilisearch, and Redis
4. cd frontend && npm install
5. cd backend && sh mvnw dependency:go-offline (or just run the app; Maven resolves deps on first run)
6. Start the backend: cd backend && sh mvnw spring-boot:run
7. Start the frontend: cd frontend && npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend REST handlers live in a single ApiController per the approved API spec; business logic is delegated to services (AuthService, EventService)
- Unimplemented endpoints return a placeholder via Stubs.notImplemented(...) rather than 404, marking spec-declared but unbuilt routes
- JPA entities use explicit @Table/@Column mappings with getters/setters, no Lombok
- Custom exceptions (EmailInUseException, InvalidCredentialsException, ValidationErrorException) are mapped to specific HTTP statuses via @ExceptionHandler in ApiController
- Frontend screens are one component per approved screen under src/screens, named *.component.ts with co-located *.component.spec.ts tests
- Shared frontend concerns (API calls, icons, navigation, brand tokens) are centralized in src/lib and consumed via screen-base.ts
- Frontend API client (api.ts) sends a bearer token (session token if present, else a shared secret) on every request and normalizes errors into ApiError
- Code formatting enforced via Prettier (frontend) and Spotless/Checkstyle (backend)

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| Backend fails to start or can't reach a database | Without DATABASE_URL set it falls back to an in-memory H2 database; for Postgres, run `docker-compose up -d` and set DATABASE_URL/credentials accordingly. |
| JWT signing/parsing errors at runtime despite compiling fine | jjwt-api is compile-time only; ensure jjwt-impl and jjwt-jackson runtime dependencies (already in pom.xml) are on the classpath when running the packaged jar. |
| Login/logout works but tokens aren't revoked on sign-out | Session-token revocation depends on Redis (REDIS_URL); if Redis is unset or unreachable, login/logout still function but without early revocation. |
| `npm run build` succeeds but `tsc`/type errors appear elsewhere | Run `npm run typecheck` (ngc) to catch Angular template/type issues that Vite's esbuild-based build does not catch. |
| Playwright e2e tests fail to start servers | Without E2E_BASE_URL set, Playwright builds/serves the frontend and packages/runs the backend itself per playwright.config.ts; ensure Java/Maven are available locally for the backend webServer step. |
<!-- sdlc:auto:end troubleshooting -->
